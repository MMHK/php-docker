## Background & Goals

`v7.4-fpm` 最近一次發版（run
[42989634142](https://github.com/MMHK/php-docker/actions/runs/42989634142)，job
`php-fpm-release` / ID 130419050188，2026-11-11T08:46Z）**arm64 失敗、amd64 成功**，
job 總時長 1h2m16s，最終 exit code 100。

失敗點不是 PHP 7.4 或 arm64 的相容性問題，而是 **QEMU 使用者態模擬崩潰**。log 直接可見：

```
#34 [linux/arm64 13/26] RUN ... docker-php-source extract; patch ...; ./configure ...; make -j "$(nproc)" ...
#34 57.37 qemu: uncaught target signal 11 (Segmentation fault) - core dumped
#34 57.46 Segmentation fault (core dumped)
```

buildkit 透過 `/dev/.buildkit_qemu_emulator` 執行 arm64 的 PHP 編譯，跑到一半 QEMU 自己
segfault。這是模擬環境下編譯大型 C 專案的已知不穩定行為，與 `Dockerfile` 內容無關。

同時 `.github/workflows/release.yml` 的註解寫著：

```yaml
# 注意：GitHub Actions 的 arm64 為原生 runner（非 qemu），不受本機 qemu segfault 影響
```

這句話是錯的：workflow 只有 `runs-on: ubuntu-latest`（x86_64），
`platforms: linux/amd64,linux/arm64` 的 arm64 全部是 QEMU 模擬，而且沒有
`setup-qemu-action`，等於隱性依賴 runner 映像剛好預裝 binfmt。

### 為什麼 Dockerfile 不用改

- PHP 編譯段以 `dpkg-architecture --query DEB_BUILD_GNU_TYPE` 與 `DEB_BUILD_MULTIARCH`
  決定 `--build` 與 `--with-libdir`，沒有硬編 `amd64`。
- 唯一的架構分支是 `$(test "$gnuArch" = 's390x-linux-gnu' && echo '--without-pcre-jit')`，
  與 arm64 無關。
- `scripts/install-extensions.sh` 沒有任何 `uname` / `arch` / `platform` 判斷；PECL 套件是
  固定 tarball + SHA256 解壓後**從原始碼編譯**，不是取預編譯二進位。

結論：**問題在 CI 產生 arm64 的方式，不在 Dockerfile。**

### Goals

1. `7.4-fpm` 的 arm64 映像由**原生 arm64 runner**建置，移除 QEMU 模擬路徑。
2. 兩個平台都成功才更新 Docker Hub tag，不留下單一平台的半成品 manifest。
3. 每個架構使用獨立的 GHA cache scope。
4. 不改 `Dockerfile`、不改 `scripts/install-extensions.sh`、不改變 image 內容行為。

### Non-Goals

- 不處理 `Dockerfile` 的 CA bundle 層（目前抓可變的 `cacert.pem`、無 checksum）——屬獨立技術債。
- 不升級 PHP 7.4 / bullseye（均已 EOL）。
- 不調整 extension 清單或 FPM 參數。

## Design Decisions

1. **兩個架構各自用原生機器建置**（matrix，不再單 job 雙平台）
   - `linux/amd64` → `ubuntu-latest`（x86_64）
   - `linux/arm64` → `ubuntu-24.04-arm`（原生 arm64，無 QEMU）
   - 本 repo 為 **public**，該 label 為 4 vCPU / 16 GB 且免費；私有 repo 自 2026-01-29
     起支援同 label 但為 2 vCPU。
   - `fail-fast: false`：arm64 失敗不會連帶取消 amd64，方便分辨是否架構專屬問題。

2. **push-by-digest + 獨立 merge job**（沿用 `8.0-fpm` 分支已落地的做法，commit `0c0d046`）
   - build job 只 `outputs: type=image,...,push-by-digest=true,name-canonical=true,push=true`，
     不直接寫 `7.4-fpm` tag。
   - digest 以 artifact 傳遞（`actions/upload-artifact@v4` / `download-artifact@v4`，
     `merge-multiple: true`）。
   - `merge` job `needs: build`，用 `docker buildx imagetools create --tag ...:7.4-fpm` 合成
     manifest，最後 `imagetools inspect` 驗證兩個 platform 都在。
   - 好處：任一架構失敗時 Docker Hub 上的舊 `7.4-fpm` tag 完全不受影響；舊 workflow 的
     `push: true` 有可能在失敗時留下不完整狀態。

3. **cache scope 依平台切分**：`type=gha,scope=${{ matrix.platform }}`。舊版兩個架構共用
   同一份 GHA cache，命中率低且互相污染。

4. **加 `concurrency`**：`group: ${{ github.workflow }}-${{ github.ref }}`、
   `cancel-in-progress: false`，避免兩個 tag 同時 merge 互踩 manifest。

5. **加 `workflow_dispatch`**（建議，Plan 內列為 Task 2）：本次改動需要「不發版也能試跑」，
   否則只能靠 push 臨時 tag 觸發（會真的推 image 到 Docker Hub）。

6. **刪掉錯誤註解**：現有「arm64 為原生 runner」的說明必須移除或改寫成正確描述，避免誤導
   後續維護者。

### 與 8.0-fpm 分支的差異（不可直接 cherry-pick）

- tag 名稱不同（`7.4-fpm` vs `8.0-fpm`）。
- 舊註解不同（7.4 分支那句錯的註解在 8.0 分支不存在）。
- 7.4 分支沒有 `opcache.ini`，extension 清單含 `mcrypt`/`snmp`/`ffi` 等，與 8.0 不同。
- 因此只可參照 8.0 的 workflow **結構**，內容需逐行套用到 7.4 分支。

## Implementation Sketch

```yaml
# .github/workflows/release.yml（7.4-fpm）
on:
  push:
    tags: ['v*']
  workflow_dispatch: {}          # Task 2 建議

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: false

jobs:
  build:
    runs-on: ${{ matrix.runner }}
    timeout-minutes: 300
    strategy:
      fail-fast: false
      matrix:
        include:
          - { arch: amd64, platform: linux/amd64, runner: ubuntu-latest }
          - { arch: arm64, platform: linux/arm64, runner: ubuntu-24.04-arm }
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      - uses: docker/setup-buildx-action@v3     # 原生單平台，無需 setup-qemu-action
      - id: build
        uses: docker/build-push-action@v6
        with:
          context: .
          platforms: ${{ matrix.platform }}
          outputs: >-
            type=image,name=${{ secrets.DOCKERHUB_TEAM }}/php-docker,
            push-by-digest=true,name-canonical=true,push=true
          cache-from: type=gha,scope=${{ matrix.platform }}
          cache-to: type=gha,mode=max,scope=${{ matrix.platform }}
      - run: |
          mkdir -p "${{ runner.temp }}/digests"
          digest="${{ steps.build.outputs.digest }}"
          touch "${{ runner.temp }}/digests/${digest#sha256:}"
      - uses: actions/upload-artifact@v4
        with:
          name: digests-${{ matrix.arch }}
          path: ${{ runner.temp }}/digests/*
          if-no-files-found: error
          retention-days: 1

  merge:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
        with:
          path: ${{ runner.temp }}/digests
          pattern: digests-*
          merge-multiple: true
      - uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      - uses: docker/setup-buildx-action@v3
      - working-directory: ${{ runner.temp }}/digests
        run: |
          sources=()
          for digest in *; do
            sources+=("${{ secrets.DOCKERHUB_TEAM }}/php-docker@sha256:${digest}")
          done
          docker buildx imagetools create \
            --tag "${{ secrets.DOCKERHUB_TEAM }}/php-docker:7.4-fpm" \
            "${sources[@]}"
      - run: docker buildx imagetools inspect "${{ secrets.DOCKERHUB_TEAM }}/php-docker:7.4-fpm"
```

## Risks & Mitigations

| 風險 | 影響 | 對策 |
|---|---|---|
| PHP 7.4 + bundled pcre 在原生 aarch64 編譯失敗（pcre2 JIT 平台支援） | arm64 leg 失敗 | 先看實際錯誤；必要時在 arm64 加 `--without-pcre-jit`，但這是 Dockerfile 變更，需人類確認 |
| PECL 套件（`mcrypt` 1.0.9 / `imagick` 3.8.1）在 arm64 原生編譯失敗 | arm64 leg 失敗 | 失敗時保留 amd64 結果不被覆蓋（digest 機制已保證）；再評估 fix 或暫時只出 amd64 |
| `ubuntu-24.04-arm` 排隊較久 / 可用性波動 | 發版延遲 | 已設 `timeout-minutes: 300`；必要時改自架 arm64 runner |
| 私有 repo 情境下 arm64 只有 2 vCPU | 建置變慢 | 本 repo 為 public（4 vCPU）；若改私有需重新評估時限 |
| 首次執行冷 cache（新 scope） | 首次較慢 | 後續改動命中 cache；`mode=max` 已開啟 |
| `workflow_dispatch` 試跑會真的推 image | 覆蓋 `7.4-fpm` tag | 試跑前確認 Docker Hub 舊 digest 已記錄，或改用臨時 tag |
| Tag `v7.4-fpm` 覆寫屬破壞性操作 | 歷史 tag 位移 | 執行前需人類明確確認；建議保留舊 digest 於 release notes |
| Node.js 20 deprecation 註解（`checkout@v4` 等被強制跑 Node 24） | 未來 action 失效 | 選配：升級 `actions/checkout@v5` 等；本次不做亦可 |

## Rollback

- **CI 層**：revert 本次 commit，workflow 回到單 job QEMU 版本（功能上可回復，但 arm64 仍會
  不穩定，不建議長期停留）。
- **Image 層**：`7.4-fpm` tag 的舊 manifest digest 仍存在於 registry，可用
  `docker buildx imagetools create --tag mmhk/php-docker:7.4-fpm mmhk/php-docker@sha256:<舊 digest>`
  指回上一個可用版本。
- **Tag 層**：若 `v7.4-fpm` 已被移動，可將 tag 指回 `9c67274` 並再次 force push。
